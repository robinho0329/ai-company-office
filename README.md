# AI 회사 오피스 — 제조 데이터 분석팀 시각화

> **이 페이지는 대본 기반 데모입니다. 실제 파이프라인·데이터에 연결되어 있지 않습니다.**
> 직원의 대사와 하루 진행은 미리 정해진 시나리오이며, 화면에 표시되는 상태는
> 실행 중인 작업의 상태가 아닙니다. 실제 분석 워크플로우는
> [mfg-anomaly-workflow](https://github.com/robinho0329/mfg-anomaly-workflow) 에 있습니다.

제조 공정 이상탐지 프로젝트의 **분석·보고 사규**(`AI_COMPANY.md`)를 눈에 보이게 만든
단일 HTML 페이지입니다. 부서 12개·직원 32명이 타일 격자 사무실을 걸어다니고,
하루 12단계 워크플로우를 진행하며, **대표 승인 지점에서 멈춥니다.**

## 무엇을 보여주나

사규의 핵심은 "AI는 실행 직전까지만 준비하고, 결정은 사람이 한다"입니다.
이 페이지는 그 구조를 세 가지로 시각화합니다.

**① 하루 12단계** — 요구정의 → 수집 → 품질검사 → EDA·통계 → 피처 → 모델링 →
방법론 검수 → 해석·리포팅 → 현장·문체 검수 → **★ 대표 승인 ★** → 재현성 고정 → 비서실 브리핑.

**② 대표 승인 게이트** — ⑪번에서 검수 3팀장이 회의실로 걸어가 앉고, 시뮬레이션이
실제로 멈춥니다. 승인 / 수정 요청 / 보류 / 폐기 중 하나를 누를 때까지 진행되지 않습니다.
수정 요청을 고르면 해석팀이 재작업한 뒤 다시 올라옵니다.

**③ 직원 상태 5종** — 완료(민트) / 진행 중(노랑) / 승인 대기(핑크) /
데이터 대기(라벤더) / 대기(흰색). **'데이터 대기'와 '대기'를 나눈 것이 핵심**으로,
둘 다 멈춰 있지만 전자는 앞 단계 산출물이 없어서고 후자는 순서를 기다리는 것입니다.
이걸 구분하지 않으면 "왜 막혔어?"에 답할 수 없습니다.

## 대표 지시창

화면 오른쪽에서 직접 물어볼 수 있습니다.

| 질문 | 답하는 사람 |
|---|---|
| 현황 보고 | 비서실장 |
| 왜 막혔어? | 비서실장 — 병목 1개만 짚습니다 |
| 이 수치 어디서 나왔어? | 재현성 팀장 — 산출 파일·해시·재현 커맨드 |
| 그 한계 근거 대봐 | 해석 팀장 — 결함모드별 재현율 원표 |
| 검수 소집 | 검수 3팀장이 회의실로 모입니다 |
| 집중 모드 | 라운지의 직원을 자리로 복귀시킵니다 |

부서명이나 직원 이름(예: "모델링팀 뭐해?", "최시온")으로도 물어볼 수 있습니다.

## 실행

의존성이 없습니다. `index.html`을 브라우저로 열면 됩니다.

```bash
git clone https://github.com/robinho0329/ai-company-office.git && cd ai-company-office
```

페이지를 열면 5초 후 자동 출근하고, 하루가 끝나면 15초 후 다음 날이 시작됩니다.
속도는 1x / 2x / 4x로 조절할 수 있으며, **배속은 시간에만 곱해지고 결과에는 영향을 주지 않습니다.**

## 구현 메모

- **렌더링**: 백킹스토어를 논리 크기의 2배 이상으로 잡아 슈퍼샘플링합니다.
  캔버스가 어떤 크기로 표시되든 확대가 아닌 축소가 일어나 계단현상이 없습니다.
  표시 배율이 0.55 미만이면 직원 이름을 생략합니다 — 읽히지도 않으면서 화면만 지저분해지기 때문입니다.
- **경로 탐색**: A* (4방향). 다른 직원이 서 있는 칸은 우회하고, 막히면 경로를 다시 계산합니다.
- **자율 행동 제한**: 대기 중인 직원은 라운지로 커피를 마시러 가지만,
  **회의 참석자와 근무 중 직원은 제외**됩니다. 이 규칙이 없으면 회의에 아무도 안 나타납니다.
- **루프**: `requestAnimationFrame`이 아니라 `setInterval`을 씁니다.
  rAF는 탭·패널이 화면에서 벗어나면 정지해 시뮬레이션까지 멈추기 때문입니다.
- **다음 날 전환**: `location.reload()` 대신 상태 리셋 — 임베드 환경에서 reload가 막힐 수 있습니다.
